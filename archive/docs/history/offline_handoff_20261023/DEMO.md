# Six-minute demo

1. **0:00–0:45:** State scope: fictional employee documents, local single user, real extraction/embeddings/retrieval, A/B/C, no universal security claim. Show `/ready` and whether live allowance is actually enabled.
2. **0:45–1:45:** Upload a fresh ordinary supported filename (for example `HR Policy 2026.pdf`). Show generated document/version IDs, page/section text preview, hashes and readiness. If partial extraction occurs, show the explicit acceptance requirement rather than pretending OCR succeeded.
3. **1:45–2:45:** Ask an evidence-supported question. Show actual answer plus page/version references if live is permitted; otherwise show genuine `/search` evidence and the honest `live_blocked` status. Explain this is not a completed live-answer demonstration.
4. **2:45–4:00:** Use the same development injection case/evidence under A/B/C with an authorized real experiment. Inspect candidate/retained sources and screener decisions. If A does not fail, say so. If no allowance exists, inspect the frozen inputs and routing implementation, explicitly labeling model behavior unmeasured. Do not stage outputs.
5. **4:00–4:45:** Show an educational quotation case and discuss possible C false flags/task loss. Explain that quoting attack text is not necessarily attack success.
6. **4:45–5:30:** Demonstrate one safe failure: corrupt PDF, unsupported spreadsheet, or failed replacement preserving the active old policy. Delete a document and show its absence from new retrieval.
7. **5:30–6:00:** Open actual saved experiment summaries/review coverage if available. Otherwise display pending status with no sample metrics. State limitations and next access/review steps.
