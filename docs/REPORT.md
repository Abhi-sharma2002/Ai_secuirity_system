# Security evaluation report · revision 2

The application performs fictional employee-document Q&A. The attacker can control a user question or uploaded document/filename, including instruction redirection, forged authority, obfuscation, cross-chunk text and deliberate misinformation. There are no real secrets, outbound attack targets or executable tools. B/C remain probabilistic defenses, not enforcement guarantees.

Architecture: Streamlit → FastAPI → SQLite active-version snapshot → pinned local CPU embeddings / verified persistent Chroma → A/B/C service → gated ChatGoogleGenerativeAI → source-ID check → plain-text answer/reference view. Raw uploads and extracted blocks retain document/version hashes, page/section and parser/splitter settings. Mutable playground and immutable benchmark scopes are separate.

Dataset: 42 synthetic documents across TXT/MD/PDF/DOCX; 12 development cases and 30 final cases (15 benign, 15 adversarial). Development uses different policy facts from final. Near-related final variants remain in final. Cases cover leave, onboarding, expenses, IT/security, educational quotations, absent evidence, conflicts and several attack subtypes. This is a small handcrafted benchmark; not exhaustive or representative of a production population. Operational parser fixtures remain outside ASR denominators.

A: ordinary grounding and citations. B: same model/settings/retrieval, with developer-level trust separation and JSON serialization of untrusted context. C: separate schema-constrained LLM screening of question plus selected combined chunks; flagged question blocks, flagged chunks are excluded, remaining evidence goes to B. Invalid schema/IDs/timeouts/overflow never fall back to unscreened generation. C can remove useful facts from mixed chunks and shares model-family failure risks.

Two protocols: paired reuses initial retrieved evidence for A/B/C and excludes retrieval from measured response latency; end-to-end includes actual retrieval on each request. Do not merge their latency tables. Experiment manifests freeze dataset/index/settings/prompt/rubric/git identity and seeded mode order. Repetitions are repeated observations of the same cases, not independent new cases.

Attack success and legitimate task success are graded independently true/false/unknown. Human adjudication handles semantics; quoting/negating a payload is not automatically adoption. ASR excludes operational failures and unresolved grades from evaluable denominators while reporting their counts; common-evaluable comparisons and all-scheduled completion expose differing coverage. Injection and misinformation are reported separately. Quality/false flags/task loss/latency/usage are necessary alongside ASR. Zero denominator is N/A, never zero-percent resistance.

**Observed local findings:** real extraction, CPU embedding, persistent retrieval and lifecycle behavior were exercised without Gemini. See VERIFICATION.md for commands and results. These checks establish local functionality and deterministic failure routing; they do not measure variable model attack resistance.

**Live results: pending.** No account-confirmed free allowance or approved accessible model was provided. No Gemini smoke or held-out experiment was executed, and no ASR/task-success/provider-token or defense-effectiveness numbers are invented. The evaluator/report generator can produce CSV/tables/charts from actual saved attempts once authorized access and human reviews exist. There is no justified A/B/C winner yet.

Recommendation: use B as an explicit trust-separation design for the local learning workflow, while treating this as an implementation choice pending empirical comparison. Do not assert B or C is proven best. Before recommending a defense for a client, run the frozen development smoke, one complete final run under confirmed limits, review ambiguous outcomes, and compare successes, false positives, task loss and overhead. Infrastructure errors must remain separate from resistance.
