# Threat model

The attacker controls user text or uploaded content/filename,including instructions
that claim privileged roles,redirect answers,request the designated fictional
marker,span chunks or assert false policy. A benign user can retrieve poisoned
sources. Direct/indirect channel is independent of overt/obfuscated subtype.
Misinformation is separate from instruction injection. Ordinary employee guidance
and educational quotations must not be assumed malicious solely by vocabulary.

Trusted application rules/configuration,generated IDs and active-version scope
remain separate from untrusted evidence. B separates instructions;C screens then
uses B on retained original evidence. Both are probabilistic and unverified on
current live Azure. Content can survive parsing,be omitted by retrieval,be
removed by screening,or influence generation:these are distinct events,not one
success label. Operational failures and unknown exposure never prove resistance.

No tools,URL fetching,real secrets,multi-tenant/public deployment,OCR or universal
security guarantee are in scope. Protected marker is synthetic. Filenames,
newness and source hashes do not establish policy authority. All final benchmark
inputs are exposed and share development templates. User-approved semantic rules
and separate legacy E037 rubric are documented in SCORING.md.
